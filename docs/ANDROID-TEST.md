# Android 실기기 수신 체크리스트

이 문서는 실행 결과가 아니라 **사용자가 실제 배포 후 수행할 검사표**입니다. 로컬 자동 테스트로 대체할 수 없습니다.

## 순서

- [ ] A가 새 공간 생성, A의 복구 코드 별도 보관.
- [ ] B가 초대 참여, B의 복구 코드 별도 보관. 세 번째 브라우저 참여 거부.
- [ ] A와 B가 각각 200ml 기록. 화면 복귀/새로고침 후 서로의 합계 확인.
- [ ] 0ml, 목표 초과, 직접 입력, 본인 수정·삭제, 상대 기록 읽기 전용 확인.
- [ ] 23:59/00:00 경계에 기록하고 과거 날짜 화면에서 일자 확인.
- [ ] 각 기기 첫 “시작하기”에서 권한 허용. 다음 리마인더를 누르지 않아도 서버 활성 기기 수와 브라우저 구독이 연결되는지 확인.
- [ ] 권한이 이미 허용되고 구독은 없는 기기에서 앱을 열면 자동 등록되는지 확인. 미결정인 기존 계정은 첫 화면 안내에서 허용.
- [ ] 나중에 하기/구독 해제 후 새로고침해도 자동 등록·권한 안내가 반복되지 않는지 확인.
- [ ] “알림 없이 시작하기” 선택 시 권한 창이 뜨지 않고, 메인의 리마인더에서 나중에 바로 허용할 수 있는지 확인.
- [ ] 각 기기의 테스트 알림이 OS에 표시됨. 잠금화면 표시와 알림 클릭 시 앱의 오늘 화면 열림.
- [ ] 고정 시각 두 개를 앞으로 3분·5분 뒤로 지정하고 오늘 요일을 켜서 저장.
- [ ] 화면 켠 상태의 예정 수신과 두 번째 지정 시각 수신 확인.
- [ ] 화면을 잠그고 최소 두 예약 구간 동안 수신 시각 기록.
- [ ] 앱을 최근 앱 목록에서 닫은 뒤 확인. **설정 → 강제 중지**와 구분.
- [ ] Wi-Fi↔모바일 데이터 전환 후 확인.
- [ ] 잠깐 오프라인 후 온라인 복귀: 푸시 TTL 15분 및 누락 가능성 확인.
- [ ] 절전 모드 켠 상태/끈 상태 비교. 지연·누락 여부 기록.
- [ ] 목표 달성 시 예약 중단. 기록 삭제로 목표 아래가 되면 다음 슬롯부터 재개.
- [ ] A의 예약만 비활성화 후 A는 중단, B는 계속 수신.
- [ ] 알림 요일 제외/22:00~02:00 자정 넘는 일정 확인. 시작 요일 기준으로 판정.
- [ ] 브라우저 권한 거부 UI와 재허용/재등록 안내 확인.
- [ ] 이 기기 구독 해제 후 서버 활성 수 감소, 다음 슬롯 알림 중단.
- [ ] 다른 기기에서 복구하면 기록/설정 유지, 이전 세션 만료, 새 복구 코드 발급.
- [ ] 모든 구독 해제 후 현재 기기만 다시 등록. 분실 기기 알림 중단.
- [ ] 프론트엔드 새 버전 배포 후 업데이트 배너/재로드/기존 세션 유지 확인.
- [ ] Cloudflare Cron 이벤트와 D1 `accepted/expired/retry/failed/unknown` 결과 점검.
- [ ] Cloudflare Free에서 HTTP/Cron CPU, 1102 오류 및 D1 행 사용량 점검.

서버 accepted만으로 이 표의 결과를 성공으로 표시하지 마세요. 실제 알림을 확인할 수 없다면 미확인입니다. 장기간 화면 꺼짐에서의 수신은 여러 날 관찰하는 것이 좋습니다.

## 실패 분기

1. **서버가 시도하지 않음**: Cron 설정 전파, enabled, 요일, 현지 시간대, 시작 포함/종료 제외, 목표량, 유효 구독, CPU 제한을 확인.
2. **서버 failed/expired**: VAPID 키/subject, key 교체 여부, endpoint 허용 목록, 구독 재등록을 확인.
3. **서버 retry/unknown**: 공급자 장애/네트워크 불명. unknown은 중복 억제를 위해 재전송하지 않음.
4. **accepted인데 기기 미표시**: Android 앱 알림, Chrome 사이트 권한, 절전, 네트워크, 앱 강제 중지, SW 설치/오류 확인. 수락과 표시 사이의 플랫폼 한계를 기록.

테스트가 끝나면 목표·시간·요일을 실제 사용 값으로 되돌립니다. 일상용 알림을 놓치면 곤란한 의료 목적의 알람으로 사용하지 마세요.
